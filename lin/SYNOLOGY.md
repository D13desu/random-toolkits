# Synology NAS Troubleshooting — Linux Toolkit 0.6.0

Run the existing Linux launcher under **Bash 4+**, then choose **13**. This module does not assume that DSM's default login shell is Bash. Review/download the script first; use an existing root session for protected checks or file moves. The toolkit never invokes sudo, installs packages, requires Entware, changes PATH, disconnects sessions, edits ACLs, restarts services, runs SMART tests or modifies storage configuration.

## Menus and workflow

1. **System/compatibility:** model, DSM version/build, hostname, kernel/architecture, uptime, privileges and absolute utility paths. DSM detection requires `/etc.defaults/VERSION` and a Synology configuration file. The resolver checks PATH executables, then `/usr/syno/bin`, `/usr/syno/sbin`, `/usr/local/bin`, `/usr/local/sbin`, `/usr/bin`, `/usr/sbin`, `/bin`, `/sbin`; executable symlinks are accepted. Missing optional tools do not prevent loading.
2. **SMB:** complete session/user/client, process, share and lock views; literal file-path search and session-text filters; safe effective Samba settings; SMB status and bounded recent error context. Flags are checked against installed help. JSON is used when supported and Python 3 is available; unrecognized/missing JSON fields fail closed. The text fallback retains full rows and never splits filenames on spaces. No text match means only no matching text, not a verified absence of active handles. PID-to-session results are candidates, not definitive per-handle identity when multiple users share a server PID.
3. **ACL:** ownership, explicit/inherited entries, unresolved identities, effective user access, parent/child comparison and optional traversal (depth 0–5, at most 200 inspected objects, no symlink traversal or filesystem crossings). `synoacltool -get-perm` is authoritative for filesystem ACLs. The module does not implement its own ACL evaluator. Blank identity names are not assumed deleted; numeric IDs are resolved only when an ID is actually available. Group-name text overlaps are advisory because aliases, spaces and nested AD groups prevent reliable comparison by splitting `id -Gn`.
4. **Office:** inspect/find `~$` owner files with bounded recursion (depth 0 means the selected directory only), metadata, age and creation time when available. Optional `strings` extraction is limited to 64 KiB files and displays heuristic Office-name candidates, separately from filesystem owner and SMB identity. Stripping `~$` identifies only an apparent original: Office may truncate/change names. Missing handles and old files never establish that editing has stopped.
5. **Identity:** `id` first, `/etc/passwd` and `/etc/group` for local numeric IDs without password fields, help-gated native local enumeration and `wbinfo` resolution/connectivity. A failed lookup is inconclusive. Neither `getent` nor legacy `synoservice` is required.
6. **Shares:** literal effective share paths, safe configuration directives, optional native enumeration and root ACL. Path macros cannot be resolved reliably. Advanced Share Permissions always require DSM verification: **Control Panel → Shared Folder → Edit → Advanced Permissions**.
7. **Storage:** utilisation, mounts, RAID status, explicit SMART attribute/health request, help-gated native information and explicit on-demand folder-size scan. No tests, repairs or destructive flags. Commands use a 20-second timeout where `timeout` exists; otherwise a request may take longer. Existing kernel logs are filtered/bounded, not treated as a complete health history.
8. **Services/packages:** installed-help-gated list/status only; unavailable syntax is reported, with listening-port and log views. DSM command vocabulary differs by build; no guessed service-management fallback runs.
9. **Network/system:** existing Linux resource summary, interface/IP/route/neighbour queries with BusyBox-friendly fallbacks, sockets and validated DNS input.
10. **Guided read-only-file troubleshooting:** target and affected user, memberships, containing share, root/parent/file ACLs, authoritative effective write flags, inheritance/unresolved evidence, SMB lookup, apparent owner file and explicit manual checks. It never writes to the original document. It does not claim a confirmed root cause or complete end-to-end SMB access. A missing Windows read-only-attribute check remains manual.
11. **Export:** last guided report's curated findings only, into an existing current-user-owned mode-700 directory. Files are created uniquely with mode 600. Raw logs, full configuration, sessions and owner-file strings are excluded to avoid exporting credentials/private configuration. Reports still contain sensitive paths/usernames; keep them private.

Permission legend: `r` read/list, `w` write/create files, `x` execute/traverse, `p` append/create directories, `d` delete, `D` delete children, `a/A` read/write attributes, `R/W` read/write extended attributes, `c/C` read/change permissions, `o` take ownership. Missing `D` on a file is expected. Level 0 is explicit; positive ancestor levels are inherited. Unknown or conflicting permission output stays unavailable rather than being interpreted as denied/allowed.

## Quarantine and restoration

These are the module's only file-changing actions. They are interactive and default to cancellation:

- Require root, Python 3 and libc/kernel `renameat2(RENAME_NOREPLACE)` support. If unavailable, there is **no fallback to overwrite-prone moves**.
- Accept only real, single-link regular `~$` files no larger than 1 MiB; reject symlink path components. Original-document symlink/hard-link aliases are refused.
- Quarantine goes to `/volumeN/@d0xd-owner-quarantine/<timestamp>-<unique ID>/owner-file` on the **same filesystem**, outside resolved effective share paths. Unresolved/missing share paths block quarantine. Root and transaction directories must be root-owned mode 700; manifests are mode 600. Configure a private administrator-controlled volume, and verify DSM does not separately expose this directory. Variable/dynamic share configurations can make quarantine unavailable.
- Show source and destination, obtain a structured SMB snapshot and refuse matching owner/original handles, require typing **NOBODY IS EDITING**, then recheck immediately before the move.
- Save a non-executable JSON manifest containing original path, payload path and filesystem identity/size/mtime before moving. Use directory descriptors and no-overwrite rename, and verify identity afterward. Rename preserves file metadata; it does not touch original Office document contents.
- Restore by selecting the private manifest. Validate payload/manifest identities and directory ownership, repeat SMB checks and confirmation, refuse any newly created owner file, and restore only the original path without overwriting. Retain the manifest after restoration. A prepared manifest can also remain after a failed move; inspect both locations before retrying.

SMB snapshots and a user's confirmation cannot eliminate races with editors or activity through other protocols, aliases or clients. These are safeguards, not a guarantee of safe removal from an actively edited document. If the installed Samba lacks supported JSON, Python is absent, the schema is unknown or queries fail, **quarantine/restore are unavailable**. Read-only diagnostics remain available. Never remove owner files simply because a text search has no matches.

## Compatibility and validation

The supplied production availability matrix is recorded in `tests/fixtures/synology-commands.tsv`. Availability does not establish argument support. The provided production-verified forms are `synoacltool -get PATH`, `synoacltool -get-perm PATH USER`, and `id USER`. All are passed as separate literal arguments, preserving spaces, Unicode and domain backslashes. Synology native list/get/status/info operations remain help-gated and version-dependent; lack of usable help leaves them unavailable. This release has **not been run on a physical DSM NAS by CI or this implementation session**.

Automated checks: Bash syntax, existing Linux regression suite, fixture-based command resolution/error classes/ACLs/SMB/Office workflows/report protection, and real temporary-filesystem transaction tests. Transaction tests substitute only a temporary volume prefix and test-user identity checks; production source remains root-gated. They test no-overwrite restore, metadata retention, collisions, symlinks/hard links, tampered payloads and unchanged original-document content. They do not validate DSM's libc, volume layout, Synology ACL behavior, Samba completeness or live-editor races.

Physical-NAS validation still needed: detected DSM/model data, installed help syntax, DSM ACL output and native list/status commands, JSON schemas for installed Samba, SMB session correlation, effective share paths/advanced permissions, read-only storage commands, owner file username formats, private volume directory exposure, renameat2 availability and live quarantine/restore with test documents only.
